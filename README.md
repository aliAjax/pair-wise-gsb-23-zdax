# hxwl-09 半导体洁净室巡检调度台

夜间巡检统一调度：巡检任务、机器人充电位、仪器借用三方联动，断网可续存、冲突双版待裁、角色分级管控。

## 技术栈

React 19 + Vite + TypeScript + CSS（纯前端状态机，无后端依赖）

## 本地运行

```bash
npm install
npm run dev        # 开发服务器 http://localhost:5109
npm test           # 56 条调度规则场景测试（esbuild 打包 engine 后在 Node 运行）
npm run typecheck  # 类型检查
npm run build      # 生产构建
```

## 调度规则

### 任务 × 机器人 × 仪器联动
- 任务按 FIFO 自动调度：必须同时有「空闲且电量 ≥ 40% 且无充电申请的机器人」与「已校准确认且未借出的匹配仪器」才可下发。
- 机器人与复检员不能抢同一台仪器：仪器 `borrowedBy` 任务级唯一，重复借用直接拒绝。
- 不满足条件的任务进入排队并显示原因（等仪器 / 等机器人 / 低电量充电中 / 冲突待裁），任务完成或资源释放后自动补下发。

### 低电量充电
- 机器人电量 < 40% 时由系统发起充电申请；作业中的机器人完成当前任务回库后才补位，不中途拉离任务。
- 充电位容量满后申请排队、任务不能下发；充满阈值 90%，充满自动完成并让出桩位给排队机器人。
- 巡检员等人工角色手动占用充电位一律拒绝（留审计记录）。

### 校准确认变更即重排
- 仪器校准确认状态一变（已确认 / 待复检 / 停用），所有未开始任务立即失效并按当前可用仪器重排。
- 进行中任务持机不受影响（仪器已在执行人手上）。

### 断网续存与幂等合并
- 基站断网：现场回传只写入本地发件箱，任务进度留存，不丢记录。
- 网络恢复：按「任务号 + 仪器号 + 进度 + 备注」幂等键合并，重复回传只入账一次，重复包标记 `duplicate`。
- 断网期间发生仪器号对不上：双版信息随发件箱留存、任务立即挂起，恢复后补入现场版台账。

### 仪器号冲突双版裁决
- 现场回传仪器号与调度台账不一致时，两版都留档，任务挂起（不可推进、不可完成）。
- 仅班组长可裁决；裁决时校验所选仪器存在、已确认、未被他任务占用。选用现场版会释放原仪器并改借新仪器。

### 角色权限
- **审计员**：全站只读，所有写操作（建任务、下发、改校准、充电、裁决、切网络）被拒绝，可查看审计日志。
- **巡检员**：可常规操作，但手动占用充电位、裁决冲突被拒绝。
- **班组长**：全部操作 + 冲突裁决。
- **厂务工程师**：常规调度与校准操作。

所有操作与拒绝均写入审计日志（操作人、动作、详情、时间、是否拒绝）。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/types.ts` | 领域模型（任务、机器人、充电申请、仪器、发件箱、台账、冲突、审计） |
| `src/engine.ts` | reducer 调度引擎：权限、下发/排队、充电位、校准重排、断网合并、冲突裁决 |
| `src/App.tsx` | 调度台界面：任务队列、机器人电量、充电位、仪器台账、冲突中心、发件箱/台账/审计 |
| `scripts/scenario-test.mjs` | 56 条端到端场景规则测试 |

## 初始示例数据

- 机器人 R-01（82%，空闲）、R-02（36%，低电量）；充电位容量 2。
- 仪器：尘埃粒子计数器 PC-A01（已确认）/PC-A02（待复检）、微压差计 DP-B01、温湿度记录仪 TH-C01（已确认）/TH-C02（停用）。
- 预置任务 T-1001/1002/1003 用于演示自动下发与低电量排队。
